# Дизайн-документ Country Search

## 1. Отмена устаревших запросов
Для предотвращения гонки запросов используется `AbortController`. При **каждом** изменении ввода (событие `input`), если есть активный запрос, вызывается `abort()`. Это происходит до срабатывания debounce, гарантируя, что устаревший ответ не придет и не перерисует интерфейс. В `catch` блоке мы различаем `AbortError` (игнорируем) и `TimeoutError` (показываем ошибку). Флаг "актуальный ответ" не используется, так как реальная отмена экономит сеть и память.

## 2. Задержка debounce
Выбрана задержка 300 мс. Если её убрать, сервер будет получать запрос на каждое нажатие клавиши, что приведет к лишней нагрузке и мерцанию интерфейса. Если сильно увеличить (например, до 1000 мс), интерфейс будет казаться "задумчивым" и медленным.

## 3. Сложность mapCountryResponse
Функция `mapCountryResponse` выполняет итерацию по массивам `languages` и `currencies`. Временная сложность — O(N + M), где N и M — количество языков и валют (обычно 1-3). Пространственная сложность — O(N + M) для создания новых массивов. В целом, для типичного ответа API это O(1) (константное время).

## 4. Принципы чистого кода
- **Single Responsibility**: `searchCountries` только делает запрос, `mapCountryResponse` только маппит данные, UI-слой только рендерит.
- **No Magic Numbers**: задержка debounce вынесена в аргумент.
- **TypeScript**: Строгие типы для `AppState`, защита от `any` в `mapCountryResponse` (используется `unknown` и проверки).
- **No innerHTML**: Динамический контент создается через `document.createElement`.
